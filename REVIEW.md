# Review

What failure looks like in this repo, for AI reviewers. A PR that passes CI can still be wrong in every way listed here — CI deliberately does not block on most of it.

## Release-blocking mistakes

- **No changeset.** A PR that changes a codemod must include `yarn changeset` output in `.changeset/`. CI will not remind anyone; without it the codemod is never tagged or published. (Docs/tooling-only PRs need none.)
- **Hand-edited versions.** `version` in `package.json` or `codemod.yaml` edited manually "to trigger a release". The Changesets bot owns both; manual edits are overwritten and cause version drift.
- **Hand-edited root README.** It is generated by `generate-readme-codemods` on the Version Packages PR. Codemod PRs leave it alone; drift is fixed on the next release PR or via `yarn readme`.

## Recipe-structure mistakes

- **Registry steps in `workflow.yaml`.** Every `js-ast-grep` step's `js_file` and every run step's `CODEMOD_SCRIPT` must be a local script; `codemod:` registry references are rejected by the test runner.
- **Wrong languages in `codemod.yaml`.** `targets.languages` must be the union of languages actually scanned by workflow steps (file selectors + run-step target files). Advertising a language nothing scans, or broadening selectors to match the manifest, is a bug.
- **Broken workflow-state coupling.** Steps that share state (an indexing step feeding a transform, a shell step reading state set by another) must run in the same workflow, in order. Reordering them "for tidiness" breaks the recipe.
- **Unscoped or wrong package names.** `package.json` `name` must use the `@backstage/` scope; the tagging/publishing scripts assume it.
- **Style drift in YAML.** Single quotes for string scalars in `codemod.yaml` and `workflow.yaml` (oxfmt convention); ids, type values, and booleans stay bare.

## Cross-platform mistakes

- **CRLF in fixtures.** Test fixtures and inputs must use LF; CRLF breaks cross-platform test comparison (a repeated failure mode in this repo's history).
- **Unbatched file lists.** Changed-file checks must batch paths (Windows argv limit), and must skip ignored test fixtures.

## Test mistakes

- **Ad-hoc test wiring instead of convention.** New steps don't change the test command: `scripts/<name>.ts` + `tests/<name>/<case>/input.<ext>` fixtures are discovered automatically; `tests/<name>/assert-fixtures.ts` covers whole-app trees; `tests/**/*.test.ts` runs under `node --test`; every `tests/**/tsconfig.json` is type-checked. Adding a bespoke wrapper suite instead of following the convention is a red flag.

## What good looks like

`yarn format`, `yarn lint`, `yarn test` pass locally — and `yarn check:changed` reproduces exactly what CI runs, so local and remote gates cannot drift. The pre-commit (`yarn lint-staged`) and pre-push (`yarn check:changed`) hooks fail loudly rather than silently skipping.
